## 3. API 与 Schema 契约

### 3.1 身份传递（全仓唯一口径）

| 通道 | 谁注入身份 | 头 | 约束 |
|---|---|---|---|
| `/api/me`、`/api/me/*` | BFF 读 NextAuth 会话 → canonical identity → HMAC 签名 | `x-navhub-user-id`、`x-navhub-identity-signature` | 客户端同名头一律剥离；匿名合并额外要 `x-navhub-anon-signature` |
| `/api/hub/*` | BFF 依 `decideHubRequest` 判决后转发；用户域写端点要求会话身份 | 同上 + `x-navhub-anon-id`（签名后） | 未登记路径 403；`read/write/admin` 一律要管理员会话 |
| 页面级专用代理（`submissions`、`videos`、`navigation`） | 同 hub 规则 | 同上 | 必须走 `anonHeaders(getIdentity())` 或 `getAnonId()`（见项目 `MEMORY.md` 强制模式） |

**写死的禁令**（沿用 `MEMORY.md`）：
- 代理层不读 anon cookie 判身份；`/api/hub/*` 只从 header/query/body 取。
- 任何"自称身份 → canonical 身份"必须用 `resolveCanonicalIdentity(ctx, identity)`，不得直调 `ctx.repo.resolveIdentity`。

### 3.3 网关判决规则（冻结）

```
public            → 放行
read / write / admin → 要求管理员会话（read 也算管理面）
未登记路径         → 403 HUB_ROUTE_UNCLASSIFIED（默认拒绝）
方法未注册但路径存在 → 按该路径最严格 scope 处理，读方法也只在 public 时放行
字面量路由优先于参数路由（/api/plugins/taps 压过 /api/plugins/:slug）
```

### 3.4 传输约束（冻结）

- body 上限：默认 **1 MB**；`backup/restore*` 放宽到 **16 MB**（依据：实测 187 字节/站，5 万条约 9.27 MB）。
- 缓存与限流：新端点显式声明——`/api/recipes`、`/api/comparisons` 为 `maxAge 300 + etag + 30/min`；`/api/sites/:id/radar` 为 `maxAge 3600 + etag + 20/min`。
- 错误封套：统一走 `apps/api/src/error-envelope.ts`（`sendError`），前端按 `code` 分支，不按文案匹配。

## 5. UI 状态规范（边界）

本规格只冻结**状态码语义**，界面表现由 O2 批次按既有错误组件实现：

- `401/403`：身份缺失或网关拒绝（`HUB_ROUTE_FORBIDDEN` / `HUB_ROUTE_UNCLASSIFIED`）→ 显示"无权限"而非"网络错误"，并保留 `code` 供排查。
- `413`：body 超限 → 恢复包场景提示"超过 16 MB 上限"。
- `429`：新端点限流（20–30/min）→ 退避重试，不自动循环。
- `400`：参数错误 → 按 `code` 展示字段级提示。

## 6. 变更例外流程

契约冻结后，任何下列改动必须先改本文件、再改代码：

1. 新增/删除端点，或改变方法、路径、scope；
2. 改变身份头名称或签名算法；
3. 改变 body 上限、缓存 TTL、限流阈值；
4. 改变错误封套字段。

流程：提出方在 `日常开发群` @架构师 → 架构师在本文件 §4 追加一行并注明日期 → 同步提醒受影响批次（O/A/S）→ 改代码 → 跑 AC2 与 AC8。
