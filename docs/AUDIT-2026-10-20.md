# NavHub 全项目深度审查报告（2026-10-20）

## 1. 范围与方法

- 对象：仓库内应用、包、脚本、CI、配置与文档；重点覆盖 API 鉴权/数据隔离、Web 跳转与 URL 边界、首屏依赖、检索与存储关键路径。

- 边界：工作区中存在 73 个同伴 WIP 文件（AI/LLM、插件市场、搜索面板、布局等），本次未覆盖/未修改；`packages/ai/*`、`packages/store/*` 按约定不碰。

## 4. 未修复的高风险项（需排期/环境）

1. **CSP 仍允许 `unsafe-inline`（中）**：`unsafe-eval` 已移除（推测意图算术改为纯递归下降解析器，不再执行 `new Function`）；`unsafe-inline` 仍受 Next 内联脚本/样式约束，需 nonce/hash 或预发 report-only 数据后再收敛。CSP 是构建期开关，enforce 前必须预发验证。**代码侧已备齐**：内置收集端点 `/api/csp-report`（有界、可脱敏）+ runbook，只需在预发开 report-only 收一周数据即可决策收哪些源。
2. **最高路由已进入 900 KB 内**：`/admin/navigation` 886 KB（预算 953,344 B），900 KB 软目标已达成；剩余体积主要是管理员共享布局与页面本体，`@hello-pangea/dnd`/`NavigationCard` 已移出首屏异步 chunk。

> 升级提示：生产环境若原本 `NAVHUB_AUTH_REQUIRED=true` 但未配置 `NAVHUB_IDENTITY_SECRET`，升级后会拒绝启动；这是有意的安全收紧，需在预发先补密钥并确认 Web 代理配置同名值。`/api/export/backup.json` 改为 admin scope，外部自动备份任务需改用 admin token。

## 6. 结论

本轮修复了 1 个开放重定向、1 个跨空间 IDOR/提权链、1 个动态工具 SSRF、1 个 URL 信任边界、1 个公开无界检索入口、1 个生产身份签名缺失导致的 IDOR 风险、1 个公开冷备泄露未发布站点的权限缺口、1 个潜在图表 CSS 注入面、两个公开导出的成本放大点与一键推仓脚本的破坏性默认值，并完成一次可实测的首屏依赖优化。相关定向测试、类型检查、Lint、Web 构建与预算门禁均通过；全量单测 `2011 passed / 15 skipped`。动态工具写请求已在逐跳 SSRF 守卫、跨源凭据剥离与请求体上限保护下开放。剩余最高优先级是 CSP 的 `unsafe-inline` 收敛，建议在预发/生产环境完成 report-only 观察与回归后再关闭对应风险项。
