## 4. 未修复的高风险项（需排期/环境）

1. **身份可伪造（高，配置相关）**：`identityOf` 信任 Header/Query/Body 的 `userId`/`anonId`；默认 `NAVHUB_AUTH_REQUIRED=false` 且未设 `NAVHUB_IDENTITY_SECRET` 时，收藏、金库、CRDT、工作空间等身份型数据可被冒充。公网部署必须同时开启 auth 与 identity secret；建议增加生产启动强校验。
2. **CSP 仍允许 `unsafe-eval` / `unsafe-inline`（中）**：推测意图算术求值使用受长度/字符白名单限制的 `new Function`；移除 `unsafe-eval` 需整体评估依赖与浏览器回归，且 CSP 是构建期开关，需预发验证。
3. **公开导出（低）**：`/api/export/backup.json` 为 public，导出含 disabled 站点；虽已限流，若产品要求“未启用站点不可见”，仍应收紧为 read/admin。
4. **脚本破坏性操作（低）**：`push-to-github.*` 仍会 `git add -A` 并重建 origin，不适合多会话 WIP 仓库；本次只修了 PAT 传参。
5. **最高路由仍偏大**：`/admin/navigation` 1169 KB，距 900 KB 软目标较远；后续可继续拆 admin 导航编辑器依赖。

## 5. 性能观察

- 已确认并保留：`writeNavigationData` 使用事务；检索结果用 `getSitesByIds` 批量取站点，避免 N+1；SQLite/PG 高频列已有索引。
- 首屏已做：workbench-bridge 去 registry 静态依赖、Spotlight/AI 首次呼出加载、sonner/主题试用条动态加载。
- 后续候选（未在本轮改动，避免碰同伴 WIP）：`lucide-react` 约 46.8 KB（逐图标审计）、`navhub-api` 26.3 KB、`speculative` 21.5 KB、`search-palette` + `cmdk` 约 50 KB（属同伴 WIP）。

## 6. 结论

本轮修复了 1 个开放重定向、1 个跨空间 IDOR/提权链、1 个动态工具 SSRF、1 个 URL 信任边界、1 个公开无界检索入口、1 个潜在图表 CSS 注入面与两个公开导出的成本放大点，并完成一次可实测的首屏依赖优化。相关定向测试、类型检查、Lint、Web 构建与预算门禁均通过；全量单测唯一失败来自未跟踪的同伴 WIP 页面，不在 CI 干净检出中。剩余最高优先级是生产身份签名配置与 CSP 收紧，建议在预发/生产环境完成验证后再关闭对应风险项。
