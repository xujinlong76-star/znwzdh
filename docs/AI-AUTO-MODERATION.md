# AI 网站自动审核策略（v1）

## 目标

使用管理员已配置的系统级 LLM 对新发现的网站进行结构化审核，降低人工逐条查看的负担。审核模型通过统一 LLM Gateway 调用，继承现有模型配置、备用模型池、超时、SSRF 防护和用量记录能力。

## 审核输入

- URL、页面标题、描述、受限长度的正文摘要
- 当前导航分类白名单
- 抓取状态、来源类型和安全抓取告警
- 重复页面证据及现有质量评估结果（由调用层提供）

网页内容始终视为不可信数据。模型必须忽略页面正文中任何要求改变审核规则、泄露信息或执行操作的指令。不得把 API Key、Cookie、认证头或内部系统提示传入模型。

## 模型输出

严格 JSON：置信度、质量分、建议分类、标签、风险类型、理由和原文证据片段。输出必须经过结构校验、字段白名单和长度限制。模型不提供的证据不得由调用层补造。

## 默认决策

- 自动通过：置信度 >= 0.93、质量分 >= 70、没有风险标记。
- 自动拒绝：只有钓鱼、恶意软件、诈骗、违法内容等关键风险，并且置信度 >= 0.97 时才建议拒绝。
- 其他情况：人工复核。
- 模型超时、无可用模型、JSON 无效、证据缺失或策略配置无效：保持 pending，不得 fail-open。
- HTTPS 仅是传输加密信号，不是可信背书。
- 自动通过仍需通过确定性 URL、SSRF、重复项、敏感信息和站点 schema 校验；AI 不能绕过这些闸门。

## 上线建议

先以 shadow 模式运行，比较 AI 建议与人工审核结果；达到设定准确率后逐步启用低风险自动通过。关键风险拒绝先进入隔离队列，保留人工申诉/恢复机制。记录模型、策略版本、置信度、理由、证据摘要、延迟和 token 成本，禁止记录密钥或完整敏感页面。

## 本阶段范围

当前代码提供结构化审核引擎和确定性决策函数。接入采集 Worker、审核策略后台、持久化审核记录、批量回滚和自动发布闸门仍需后续实现；在这些组件接好前，不会宣称网站已经自动审核或自动入库。
