# VNext 搜索、推荐、采集与治理核心策略

本目录的策略模块是纯函数层，负责统一策略和可测试契约。它们**不代替**数据库队列、采集 worker、外部情报连接器、管理端审核，也不会自行修改生产搜索/推荐排序。

## 已落地的核心契约

- `search-gold.ts`：双人独立标注、分歧仲裁、脱敏查询 ID、冻结候选快照和至少 100 条数据集门槛。不能用合成查询冒充真实用户数据。
- `recommendation-quality.ts`：首页、相似站点、AI 找站、个性化四种场景共享特征契约、独立权重；高风险是硬门控，证据不足时不使用质量分。
- `crawl-scheduler.ts`：失败分类、指数退避、随机抖动、Retry-After 下限、每域名最小间隔策略和 HTTP(S) 主机规范化。
- `content-deduplication.ts`：页面 SimHash、汉明距离、Jaccard、精确/近重复判断、经核验的域名别名族。语义向量由上层模型/向量服务提供，不在此模块伪造。
- `risk-evidence.ts`：可信来源 allow-list、有效期、最大新鲜度、独立供应商组交叉验证；此模块只输出证据判断，不自动封禁或下架。

## 生产接线顺序

1. **真实搜索金标**：从用户明确允许保留的遥测中抽样；在导出前去除身份、IP、令牌、邮箱、电话号码等可识别信息。关闭遥测或已删除的数据不能补造。冻结查询时的候选、检索通道、排序和索引版本。两名标注员独立标注，分歧由第三人仲裁。只有通过 `validateSearchGoldSet` 的数据才进入离线评测。
2. **推荐接线**：各入口保留自己的候选召回和业务约束，读取统一特征并调用 `scoreRecommendation`；高风险候选在排序前隔离。先 shadow 对照，不直接切线上流量。
3. **采集接线**：扩展现有 JobRunner 与持久化 jobs 表；队列认领必须用事务/租约/CAS，域名频控状态必须跨实例原子更新。任务到达重试上限进入可审计 dead-letter；robots/auth 限制进入人工处理，不重试绕过。
4. **去重接线**：采集正文经清洗后生成精确哈希与 SimHash；相似候选生成关系，不自动删除。语义近重复由现有向量设施提供相似度；域名族只能依据官方关联证据或人工审核维护。
5. **风险接线**：通过可配置外部情报适配器接收证据；每条记录保存供应商、证据 ID、时间、有效期、类别和置信度。单一供应商信号只触发复核；确认风险后由独立审核工作流决定隔离、警告或下架，并支持申诉/回滚。

## 上线门禁

- 不伪造真实查询或人工标签；当前真实数据规模必须由实际脱敏数据决定。
- 新推荐排序先 shadow；NDCG@10、MRR@10、Recall@20、多样性和 P95 延迟均达到门槛后再灰度。
- 风险证据未知不等于安全；质量分不得抵消高风险门控。
- 采集必须尊重 robots.txt、站点条款、Retry-After、域名限速和 SSRF 防护；不得绕过认证、验证码或付费限制。
- 所有候选合并、发布、隔离、下架操作都要有审核记录和回滚路径。

## 当前 PR 的边界

本 PR 完成可复用的核心策略、类型和单元测试。持久化 schema、API/worker 调度、外部安全情报适配器、后台工作台页面以及四个推荐入口的生产接线属于后续集成 PR；在这些接线和 CI 完成之前，不应宣称整套 VNext 已上线。
