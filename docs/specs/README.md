# docs/specs —— 立项规格落盘目录

## 本目录用途

每个大需求的立项规格（PRD + 架构契约 + 设计冻结）的**唯一落盘地**，由架构师 / 文档工程师汇总定稿。

## 文件命名约定

```
SPEC-<功能名>-<YYYY-MM-DD>.md
```

示例：`SPEC-首访信任-2026-11-27.md`

## 最小必填段落

每个 SPEC 文件必须包含以下六节，缺一不可：

1. **目标与范围** —— 本需求要解决什么问题、覆盖哪些页面/模块
2. **验收标准 AC** —— 可执行的断言清单，每条附代码位置（文件:行号）
3. **API 与 Schema 契约** —— 接口签名、请求/响应结构、类型定义
4. **UI 状态规范** —— 加载 / 空 / 降级 / 错误 / 命中各态的界面表现
5. **不做清单** —— 明确排除项，防止范围蔓延
6. **影响面与回滚** —— 改动的模块、依赖、回滚步骤与风险

## 开工门禁

日常开发群开工前必须读取本目录对应文件；**无规格不得开工**。
