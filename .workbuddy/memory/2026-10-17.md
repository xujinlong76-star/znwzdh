## 第二轮：Docker 可复现性修复（b6ae030）+ 报告结论纠错（d04aa8e）

- **根因翻案**：此前判定 api 镜像 `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH` 是"容器内重算 overrides 与 lockfile 不一致"，真实原因是 **`Dockerfile.api` 依赖阶段漏了 `COPY pnpm-lock.yaml`**（没有 lockfile 就无法 frozen）。补上后最小上下文 `pnpm install --frozen-lockfile --filter "@navhub/api..." --lockfile-only` 直接通过，已改回 `--frozen-lockfile`。教训：报 config mismatch 先查 lockfile 在不在。
- **同源漏文件**：`apps/web-overlay/pnpm-lock.yaml` / `pnpm-workspace.yaml` 被 `.gitignore:26` 的 `apps/web/*` 挡住，从未入库 → web 镜像其实是"拿上游 lockfile 装 overlay 的 package.json"。已 cp 进 overlay 并 git add。
- **`apps/web` 自成一套清单三件套**（package.json + pnpm-lock.yaml + pnpm-workspace.yaml，后者为 `packages: ['.']` + allowBuilds，因为 Docker 里是独立安装、读不到仓库根 workspace）。三者必须成套，缺 workspace 文件会 `ERR_PNPM_IGNORED_BUILDS`。
- **web 依赖层缓存**：Dockerfile.web 改两段 COPY —— 先只拷清单 install（可缓存层），再拷源码。`.dockerignore` 加 `**/node_modules`、`apps/web/**`（用 `!apps/web/package.json` 放行，api 的 frozen 校验需要它）、`*.tsbuildinfo`。
- **drizzle 结论纠错（重要）**：初稿报告称"零调用、仅 db:generate 引用"是错的。实际 `driver.ts:502/579` 两种方言都创建 `drizzle()` 实例挂在 `Db.orm`，`schema.ts:11` 用 `sqlite-core` 定义表，只是**所有查询仍走 raw SQL**。别误判成"删依赖即可"。
- Docker Desktop 本机已彻底不可达（npipe 拒绝连接），镜像改动只有静态证据，CI `docker-smoke` 复验。

## 环境坑（重要）

1. **pnpm 11 链接层会静默断裂**：`pnpm install` 报 "Already up to date" 但 importer 只剩 8 个链接；删 `node_modules/.pnpm-workspace-state-v1.json`、删根目录 `node_modules/.modules.yaml`、删 `apps/web/node_modules`、`--force` 均无法让它重链。可行修复是脚本重建 junction（用 `New-Item -ItemType Junction`，PowerShell 能处理中文路径；`cmd mklink` 传中文路径会失败）。
2. **Docker 构建 web 镜像此前从未被验证**（CI 无 docker job），实际是坏的：
   - overlay 纳入 package.json（React 19）后与上游 lockfile 的 overrides 不匹配 → `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH`；解决：为 `apps/web` 生成**独立** lockfile（`pnpm install --lockfile-only`）并纳入 overlay。
   - pnpm 11 默认忽略安装脚本并报错 `ERR_PNPM_IGNORED_BUILDS`；解决：`apps/web/pnpm-workspace.yaml`（`packages: ['.']` + `allowBuilds`）。注意 **pnpm 11 不再读 package.json 的 `pnpm` 字段**（overrides/allowBuilds 均已迁移）。
3. 并行会话活跃：git HEAD 会被 rebase/push 改写，提交可能报 `cannot lock ref`；重试即可。改动也可能被并行会话一起提交。
