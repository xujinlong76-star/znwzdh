# 采集来源安全边界

本文定义采集来源注册与实际抓取的安全边界。注册检查只是第一道门，**不能替代每次网络请求前的 SSRF 校验**。

## 注册与更新阶段

- 管理员新增或修改来源 URL 时，必须调用 `assertUrlShape` 检查协议、凭证和端口。
- 必须调用 `resolveAndCheck` 对 DNS 解析结果逐个检查；解析超时、失败、空结果均 fail-closed。
- 拒绝环回、私网、链路本地、云元数据、保留网段以及危险端口。
- 用户提交的 URL 永远不能进入 `trustedHosts` 或 `allowedHosts` 白名单。
- 注册时通过不代表未来 DNS 解析仍然安全；DNS 记录可能变化。

## 实际抓取阶段（强制要求）

任何 worker、定时任务、手动重试或预览接口，在每次请求时都必须使用 `guardedFetch`：

1. 禁止对来源 URL 直接调用原生 `fetch`、`http.request` 或 `https.request`。
2. 禁止使用自动跟随重定向的网络客户端；每一跳必须重新解析并校验目标。
3. 不得把用户可控域名加入 SSRF 信任白名单。
4. 限制请求超时、最大响应字节数和重定向次数；内容解析前再次按字节上限截断。
5. 跨源重定向不得转发 Authorization、Cookie 等凭据。
6. 对 DNS 解析失败、超时、私网目标或危险端口采取拒绝策略，并记录不含正文和凭据的安全事件。

## 测试要求

- URL 形状：非法协议、用户名/密码凭证、危险端口。
- IP：IPv4/IPv6 环回、私网、链路本地和云元数据地址。
- DNS：全部 A/AAAA 记录均检查；混合公网与私网解析必须拒绝；DNS 失败必须拒绝。
- 重定向：公网到私网、跨协议、跨源凭据清理、重定向次数上限。
- 回归：注册、更新、worker 抓取、人工重试和预览路径共享相同的安全策略。

## 上线门槛

在实际采集 worker 接入 `guardedFetch` 并通过上述重定向/DNS 回归测试之前，来源注册表只能视为配置数据，不应启用自动抓取调度。不得因为注册时校验通过，就把来源标记为运行时安全。
