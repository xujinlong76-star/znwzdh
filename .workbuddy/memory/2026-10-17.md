## 数据治理后半：明细聚合 rollup（建议 25 收尾）

- 新增 `packages/store/src/rollup.ts`（`runRollup` / `rollupDdl` / `EVENT_DAILY_ROLLUP` / `AUDIT_DAILY_ROLLUP`）。与 retention.ts 同用一个 `RetentionAdapter` 端口，方言无关。
- 产出表：`events_daily`（唯一键 `day_start,kind,site_key`，指标 `total`/去重 `identities`）、`audit_daily`（`day_start,action,actor_kind`，`total`/去重 `actors`）。首次 `--apply` 时 `CREATE TABLE IF NOT EXISTS` 惰性建表，不改 migration。
- 三个刻意的设计取舍（踩过才知道）：
  1. **只推进整天**：`effectiveCutoff = floor(cutoff/DAY)*DAY`。若某天里还有未到期行却把到期的一半聚合了，重跑会用剩下的行覆盖同一天，聚合值越算越小。
  2. **upsert 覆盖而非累加**：累加语义重跑一次就翻倍。
  3. **分组超限整天跳过**：`maxGroupsPerDay` 默认 5000，超了不写不删——宁留明细不写半份聚合。
  - 另有三重刹车防空转：单表单轮 30 天（`--max-days`）、跳过的天记进 `seenSkipped`（否则下一趟还是同一天）、dry-run 因不删行只推进一趟。
- SQL 技巧：`created_at - (created_at % 86400000)` 这个日桶表达式在 SQLite 与 PG 上都成立，所以单一套 group/upsert SQL 就够，只有占位符风格不同。PG 的 COUNT/BIGINT 会回传字符串，全部 `Number()` 归一化。
- 为什么不做月表：月长度不固定，无法用取模求桶；日聚合已约 30 倍压缩，月度口径从 `events_daily` 再 GROUP BY 即可。
- CLI：`scripts/data-retention.mjs --rollup [--apply] [--max-days N] [--max-groups N]`。`sites.visit_count` 是写入期自增、`trend_score` 由 recompute_rank 按近期窗口重算，**都不依赖 events 全量历史**，删过期明细不影响热度排序（这点很重要，删之前先论证过）。
- 验证：13 个单测（`packages/store/test/rollup.test.ts`）+ 临时 SQLite 端到端 + CLI 实跑。端到端结论：dry-run 零改动且**不建表** → apply 后 `events_daily` 的 total/identities 与明细一致 → 2.4 天前（半天过期）的那天原样保留 → 二次运行全 0 且聚合值不翻倍。

## rollup 压测 → 发现"删了不等于瘦了"，补 --vacuum

- **最重要的一条经验**：SQLite/PG 删行后都只是把页标记为空闲，文件不会自动变小。30 万行库上实测 VACUUM 前后 **29.22 MB → 6.53 MB（差 4.5 倍）**。此前脚本删完就退出，运维看到"清理执行了磁盘没降"会误判成没删掉 —— 现在两条路径执行完都打印下一步，`--vacuum` 可选执行（SQLite 跑 VACUUM；PG 只提示，因为 VACUUM FULL 锁表属运维决策）。
- 压测数据（30 万行 events，400 天 × 750 行/天）：rollup 追平 220 天 **9 轮 / 2.1s**；完整性 `聚合行数 + 剩余明细 = 原始 300,000`（这是验证聚合类逻辑最有说服力的一条断言）；幂等重跑 0 天；清理模式 60,700 行 4.3s。
- `--max-days` 不要无脑拉到 365：默认 30 天/表/轮是为了单轮事务链可控，配合"每月跑一次"自然消化。
- **门禁踩坑**：`node scripts/verify.mjs` 报过 check-web-overlay「8 漂移 3 缺失」，单独复跑却 OK —— 原因是并行会话正在同一分钟落提交，检查读到了写了一半的树。**多人协作时这类瞬时失败先重跑一次再排查**。
- 收尾顺序重构：归档 flush → VACUUM → 关连接 → 打印汇总（异常路径同样先 flush）。原先 `finally` 里既 flush 归档又关连接，和 VACUUM 抢生命周期。
- 最终整仓门禁：`node scripts/verify.mjs` 四项全过（覆盖层 216 文件一致 / 扩展 100% / tsc 0 错误 / vitest 66 文件 969 通过 11 跳过）。
