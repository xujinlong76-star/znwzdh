## 逐样本观察

### 1. hao123 —— 水平分类 chip + 内容流（门户化）

- **层级**：极浅。顶部一行水平分类 chip（网页/视频/图片/新闻/电商/购物…→美食/房产/汽车/教育/财经/娱乐/健康…），点击类目进入**一屏图标网格**，无第三层子类目。
- **分面/标签**：无站点级标签系统；类目即全部分类维度。
- **形态特点**：导航区下方约 70% 篇幅是新闻信息流（品质生活·好物精选 = 电商导购模块）——**纯导航已被门户内容稀释**，导航退化为首屏入口。

### 2. 优设导航 —— 左侧垂直单层分类 + 章节卡片（最接近 NavHub 形态）

- **层级**：左侧边栏 20+ 个类目（热门推荐/高清图库/设计教程/界面设计/灵感创意/AIGC工具/设计素材/字体下载/设计工具/设计规范/摄影美图/配色方案/前端开发/室内设计…），**全部单层平铺，无子类目**。
- **正文结构**：按类目分章节（每章节 = 一个类目的全部站点卡片网格），卡片 = 图标 + 标题 + 一句简介。
- **分面/标签**：无。每站点**唯一归属**一个类目；顶部搜索框是唯一检索入口。
- **检索**：搜索框带类型 tab（全站/图片/…），无筛选器。

### 3. QQ 导航 —— 水平分类 + 图标网格 + 大量信息流

- **层级**：与 hao123 同构——顶部水平分类 chip（娱乐/网购/AI/福利/手游/工作/生活/学习/网站/设计/汽车/…），下接图标网格分区，无深度嵌套。
- **形态特点**：中后段被视频/体育/剧集等内容区块占据（门户化程度比 hao123 更深），右侧挂热点榜。导航分类只占首屏约 30%。

### 4. 2345 移动版 —— 纯图标分组（最干净的基线）

- **层级**：一层。搜索框 + 常用（8 图标）+ 资讯/视频/财经/小说/生活/汽车分组（每组约 6–8 图标），无子类目、无 tab 切换。
- **分面/标签**：无。分组标题即分类。
- **对照价值**：移动端把「导航」还原到最简形态——**浅分组 + 图标直达**，证明国内用户对导航站的心智锚点是「分组点开直达」而非「多维筛选」。

## 跨样本结论（对应研究报告）

1. **国内主流结构 = 浅分组（1–2 层）+ 单归属 + 无标签系统** `[CONFIRMED，4/4 样本]`：
   没有任何一个样本对「站点」做多标签或分面标注；分类维度只有类目分组这一条轴。这与国际产品的「主树 + 标签双轨」（Product Hunt / Raindrop，见研究报告 §3.3）形成明确分野。
2. **没有分面筛选 = 机会而非落后**：国内无人做「付费模式/平台/形态」正交筛选，NavHub 的阶段二（受控分面）在中文导航品类里属差异化，而非抄近路的跟风需求。同时反向确认——**阶段二的分面必须渐进披露（默认折叠）**，因为目标用户没有被教育过这种交互。
3. **单归属心智极强**：4/4 样本站点都只出现在一个分组里；连优设这种 20+ 类目的专业站也不允许跨类目。研究报告 §3.3 的「主归属唯一 + 标签横切」建议与国内心智兼容——**标签应作为主树的补充（阶段一），而非替代浏览主轴**。
4. **「导航 → 门户内容流」是普遍演化路径** `[MAJORITY，hao123/QQ 2/2]`：综合导航站下半屏都变成了新闻/视频/电商流。对 NavHub 的含义：收藏、榜单、专题（collections）这些「用户向」模块与导航主业不冲突，符合品类走向；但需警惕内容流挤占导航首屏（NavHub 首页目前保持纯导航 + 搜索入口，是正确的取舍）。
5. **桌面/移动分野**：移动端（2345m）把分类压到一层；桌面端专业站（优设）才敢用 20+ 类目平铺。NavHub 若后续出移动适配，应参照「一层分组」而非桌面侧边栏。

## 方法论备注

- MCP 浏览器通道（browser_use / Chrome DevTools）在本次环境整体 IDE 超时不可用；改走 **Chrome headless CLI**（`--timeout` 而非 `--virtual-time-budget`，后者在含持续定时器的门户页会无限等待）。网络本身通畅（uisdc HTTP 200 实测），个别站点失败属反爬/渲染问题，已弃样不做过度重试。
- 反爬样本（114la）只能拿到服务端 WebFetch 残片，未计入结论样本。
