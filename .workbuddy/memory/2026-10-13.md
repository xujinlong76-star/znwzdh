# 2026-10-13

## NavHub 网址导航功能增强方案（研究 + 设计）

- 通读代码库后产出方案：`docs/navigation-enhancement-plan.md`（含需求分析、架构、数据模型、模块划分、集成方式、Phase 0-4 优先级、风险登记表）。
- 架构结论：检索/富化/MCP/存储接缝/双驱动已完整（117 测试 + 验收报告）；缺口在前端体验（搜索未接后端）、用户体系、收藏夹、标签浏览、推荐排序、定时任务。
- 研究中发现三个具体缺陷（方案内含对策）：
  1. `apps/api/src/storage.ts` 的 `writeNavigationData` 全量对齐会删除快照外站点 → 经 API/MCP 新增的站点会被前端保存误删（P0 修复：按 source 过滤）。
  2. `sites.weight` 无任何写入方，browse 排序退化。
  3. 前端 `navigation-content.tsx` 搜索是纯客户端 includes 过滤，后端四通道检索引擎未接入 UI。
- 另：`apps/api/package.json` 声明了 `migrate` 脚本但 `src/migrate.ts` 文件不存在。
- 方案关键决策：新增 favorites/favorite_folders/user_profiles/search_history 四表 + sites/users 列扩展；NavSphere 线格式零变更；个性化沿用 personal 通道（权重 0.3）不做事后加成；新出网路径强制复用 guardedFetch；新表 DDL 需 schema.ts + driver.ts 双方言 + migrate.ts 三处同步。
