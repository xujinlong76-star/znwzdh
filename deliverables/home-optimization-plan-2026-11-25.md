# 首页优化方案（2026-11-25 实测）

> 全部数字来自本机 dev server（localhost:3000，真实库 5096 站）Playwright + Chrome 157 实测；
> TTFB/DCL 受 dev 模式影响偏大，**只用于横向对比，不代表生产值**。

## 体检：问题在「重」与「首屏被占」，不在「丑」

| 指标 | 桌面 1440 | 移动 390 | 判读 |
|---|---|---|---|
| HTML 体积（未压缩） | **4.46 MB**（RSC payload 2.28MB + markup 2.17MB） | 约 3.4MB | 预算哨兵 4MB 已被顶穿 |
| DOM 节点 | **15,696** | 12,212 | 约 10 倍于健康电商首页 |
| 链接 / 按钮 | 1,163 / **1,814** | 887 / 1,443 | 每张卡 2~3 个按钮 |
| 页面高度 | **37,913 px**（42 屏） | 19,429 px（23 屏） | |
| JS 资源 | 44 个 / 1.72 MB | — | 首页预算 1,452KB 已 99% 占满 |
| 首张卡片出现位置 | y≈313（好） | **y=653**（首屏 844 只剩 191px 给内容） | 移动端问题最大 |
| TTFB / DCL | 2.7s / 4.7s | 1.8s / 3.2s | dev 口径 |

### 结构事实
- 首屏最顶是「插件精选」整块：桌面 174px，**移动端 324px（占首屏 38%）**，内容是 6 个纯文本胶囊。
- 移动端其后是：头部 93px → 分类折叠条 61px → 工作区 Tab 行 → 快捷坞（y=417）→ 才到第 1 张站卡（y=653）。
- 桌面 SSR 只渲染 2 个分类（AI 工具 96 卡、前端开发 84 卡），但「AI 工具」一个 section 就 **4,645px**，前 4,878px 页面只有 2 个分类。
- 页面底部 37,471px 处才开始页脚；中间 11,987px 处有一个 640px 区块、12,651px 处有一个 3,200px 虚线区块（DIY 占位）。
- 全部 180 张首屏卡片的 favicon 都是 `loading="lazy"`，但它们在首屏 → **浏览器仍会立刻请求**，407KB 图片里大部分是首屏图标。

## 方案（按性价比排序）

### P0 — 移动端首屏归还内容（收益最大，改动最小）

**问题**：首屏 844px 里内容只占 191px。三个「介绍型」区块（插件精选 324 + 头部 93 + 折叠条 61 = 478px）排在内容之前。

| 改动 | 做法 | 预计收益 |
|---|---|---|
| 1. 插件精选在移动端降级为一行入口 | `md:hidden` 整块，`<md` 只留「插件精选 ›」一个胶囊进快捷坞 | **−280px**，首卡上移到 ~y=373 |
| 2. 分类折叠条移入快捷坞 | 「折叠全部常用」是低频操作，不该常驻 | −61px |
| 3. 快捷坞默认收起 | 首访只显示「快捷坞 ›」 | 首屏内容 ≥ 60% |

> 注意：M-01（今天刚合入的 fea7a29b）明确要求首页**保留可见的插件精选区**。所以这条要在「可见」与「占高」之间取折中：移动端一行、桌面端保留整块。改前请确认 M-01 验收口径是否接受移动端单行。

### P1 — 砍 HTML 体积（4.46MB → 目标 <2MB）

| 改动 | 依据 |
|---|---|
| 1. **RSC payload 瘦身（−1MB 级）** | 2.28MB 的 script 里塞了全量导航数据供客户端水合。SSR 只渲 2 个分类，却把 40+ 分类全量发到客户端。改为：首屏数据内联，其余分类走 RSC 分片 / 客户端按需 `fetch`（现成的 `loadNavigationCatalog` 分片读已存在） |
| 2. **每卡 DOM 减半** | 180 卡 = 15,696 节点 ⇒ ~87 节点/卡。卡内有「速览·→ 操作1…」隐藏按钮组。非 hover/focus 态用 `content-visibility` 或 CSS `display:none` 而非常驻 DOM |
| 3. **首屏图标 `fetchpriority="low"` + 真 lazy** | 180 张首屏图标全部立刻请求；用 IntersectionObserver 真正延迟到滚动 |
| 4. 调 SSR 分类数 | `NAVHUB_HOME_INITIAL_SSR_CATEGORIES=4` 默认值下只渲了 2 个（因 EAGER_CATEGORY_COUNT=2）；统一两个阈值，避免配置与现实不符 |

### P2 — 信息架构（需要产品决策）

| 议题 | 现状 | 建议 |
|---|---|---|
| 「AI 工具」巨类 | 单类 96 卡 4,645px，子类 17 个平铺 | 默认折叠子类或分页（显示前 24 + 「查看全部 341」） |
| 页面 42 屏长 | 40+ 分类全部垂直堆叠 | 改为「分类目录 + 按需展开」或分页；`content-visibility` 已开但仍占滚动高度 |
| 展示模式 7 种 | 标准/紧凑/图标墙/列表/玻璃坞/杂志/终端 | 首访默认即可，入口收到「外观」里；7 套变体代码是 bundle 大头之一 |
| 底部 DIY 占位 | 12,651px 处 3,200px 虚线框 | 未进入编辑态不应渲染 |

### P3 — 体验细节

- **LCP 元素缺失**：PerformanceObserver 未捕获到 LCP 候选 → 首屏没有大图/大文本块作为 LCP。建议给品牌区或首张卡加 `fetchpriority` 并确认 LCP < 2.5s。
- **1,814 个按钮**：屏幕阅读器 Tab 一次要走很久。给卡片隐藏操作组加 `tabIndex=-1`，仅 focus-within 时进入 Tab 序列。
- **页脚在 37,471px**：几乎没人滚到。把「设为首页 / 我的收藏」等高频项上移到快捷坞。
- `Cache-Control: no-store`（dev 口径，生产构建确认为 ISR 60s ●），上线后复核。

## 不建议做的

- ❌ 继续加首页区块（今日中心、短剧、考试卡…都在争首屏）。首页已经是「所有功能的入口」而不是「找站的工具」。
- ❌ 用 CSS 隐藏解决体积问题——DOM 和 RSC 还在。
- ❌ 砍展示模式功能——有测试守卫且用户依赖；应砍的是**默认加载的代码**（dynamic import 已做了一半）。

## 建议执行顺序

1. P0 移动端首屏（半天，纯布局，零数据风险）
2. P1-3 图标真 lazy（1 小时，收益立竿见影）
3. P1-1 RSC 瘦身（1~2 天，需验证水合一致性）
4. P1-2 卡片 DOM（1 天，需过 a11y/交互测试）
5. P2 分类折叠（产品确认后 1 天）

每步都要重跑：bundle-budget、ISR 门禁、a11y 契约、e2e responsive-matrix。
