# 采集候选 AI 影子审核接入

## 当前实现

- Worker 采集 HTML 并创建/更新待审核候选后，可通过 `NAVHUB_CRAWL_AI_MODERATION=shadow` 显式开启 AI 影子审核。
- 使用 `resolveLlm(ctx)` 复用管理员配置的系统模型、备用模型池与密钥解析；不新增独立模型配置。
- 使用 `reserveLlmQuota` / `settleLlmQuota` 做原子额度预留，并通过 `callLlm` 记录真实模型、Token、延迟、成功/失败用量。
- 审核输入只包含 URL、标题、描述、截断正文和有限采集证据；网页文本是不可信数据，审核引擎明确防提示注入。
- 结果写入候选 `evidence.aiModeration`，保留模型、策略版本、置信度、质量分、风险、理由和证据。
- 额度不足、模型未配置、模型异常不会自动通过；模型错误只记录错误类型，避免把上游响应内容写进候选。
- 本阶段始终是 Shadow：不自动批准、不自动拒绝、不发布站点、不修改候选状态。

## 启用方式

部署环境显式设置：

```bash
NAVHUB_CRAWL_AI_MODERATION=shadow
```

未设置或设置为其他值时不调用模型，不产生 AI 审核费用。

## 下一阶段门槛

1. 建立持久化审核策略表与管理员规则 UI，配置启停、模式、阈值、风险动作、每日预算。
2. 将影子决策与人工审核结果做双人标注金标集对比，统计误放率、误杀率、人工推翻率。
3. 在规则版本、成本监控、回滚与人工复核链路完整后，才允许管理员显式开启 auto 模式。
4. Auto approve 仍必须叠加 URL/SSRF、重复、域名信誉和数据完整性等确定性校验；模型不得独自决定公开发布。
