# NavHub 页面模板文案审计与薄内容风险报告

> 审计对象：`apps/web-overlay/src/app/**` 的 metadata 与模板文案（`apps/web` 为镜像，不重复审）
> 数据源：`data/navhub.db`（sites 1020 / categories 594 / tags 1080 / collections 4 / plugins 64）
> 验证方式：直读 DB + `curl localhost:3000` 看真实渲染
> **本报告所有公式示例的站点名、计数、分类名、标签名均已回查 DB 核对**，无一为占位符——因为「示例里编数据」正是本报告要治的病。


**一句话结论**：NavHub 的内容问题不是「文案写得不好」，而是**模板在替不存在的数据说话**——1020 个站点页共用一个标题、1080 个标签页共用一个标题、`/hot` 声称按真实点击排序而 `visit_count` 全为 0、站点页承诺「平替与生态关联」而平替覆盖 9.7% 且其中 76 站是子串误命中（事实错误）、生态搭配 0 站。先改 4 个 `generateMetadata`、补 1 个分类路由、砍 3 处虚假承诺，再谈批量生产描述。

## 2. 标题 / 描述公式（可直接落地）

**两条硬约束（seo-optimizer 技术侧，已验证）**：①**子页 title/description 一律不写品牌字面量**（`NavHub`/`NavSphere`）—— `apps/web/test/route-titles.test.ts` 扫 `src/app/**` 的 metadata 字面量并断言不含品牌名，后缀由根 layout 的 `title.template` 追加；**唯一豁免是根 layout 自身**（`app/layout.tsx` 的 `title.default`），故只有首页题面带品牌，其余 6 个模板全不带。②**不写「热门/最受欢迎/评分最高」**：`visit_count`/`trend_score`/`featured` **全为 0**，无数据支撑。

**长度约束**：品牌后缀 `" - NavHub 导航"` 约占 15 半角宽（≈7.5 汉字），故**子页 title 主体 ≤22 汉字宽，含后缀 ≤30**。description 硬上限 **150 字符**（代码截断值），但 SERP 约 78 汉字即截断、`description` 均长仅 **28.2 字**——**150 是天花板不是目标**，用「原文 + 一句诚实兜底」两段式，自然落在 40–70 汉字，不为凑长度编内容。所有 `{N}` 必须实时查，取不到就删整句。

- description：`收录 {N} 个站点，按 {M} 个细分分类整理：{Top3 分类名}。支持中文语义检索与拼音混合召回，不用记英文名也能找到工具。`
- 示例：`收录 1020 个站点，按 594 个细分分类整理：AI 工具、开发运维、数据库与存储。支持中文语义检索与拼音混合召回，不用记英文名也能找到工具。`（72 汉字）

### 2.2 站点详情（拆页为服务端组件 + `generateMetadata`；**不带品牌**）
- title：`{站点名} - {description 按词边界截断，≤14 汉字且去尾部标点}`
- 示例（真实数据）：**`Cursor - AI 驱动的代码编辑器`**（≈21 汉字宽）；**`Gitee 码云 - 国内代码托管平台`**（≈20，原句尾部「，访问速度快」按标点边界去掉）
- **降级**：站点名本身 ≥16 汉字宽、或截断后不足 6 汉字 → 改用 `{站点名} · 站点详情`（仍因站点名而唯一，不会 1020 页同名）
- description（两段式，**不含品牌**）：`{description。}{兜底句}`
  - 兜底句只陈述客观事实，三选一按数据可用性降级：①`官网入口、所属分类「{分类}」、{N} 个同类站点。` ②`官网入口与所属分类「{分类}」。` ③`官网入口：{url}。`
- 示例（Gitee 码云，`description`=「国内代码托管平台，访问速度快」，分类=开发运维，tags=代码托管/国内）：`国内代码托管平台，访问速度快。官网入口、所属分类「开发运维」、12 个同类站点，另有 #代码托管 #国内 标签入口。`（52 汉字）
- 差异点：分类名、同类站点计数、标签名。**降级**：`site_relations` 为 0 → 禁止「平替」「替代关系」；**`{N}` 必须与分类 hub 同口径（`category_id` ∪ `sub_category_id` 双指针）**，否则文案里的 N 与页面实际列出条数对不上，是用户能直接看见的矛盾——68 个无 `sub_category_id` 的站点天然落在并集内，不冲突；**取不到分类名时整段省略，不写「同类站点」占位**；`last_checked_at` 为空（874/1020）→ 不写核验时间；**禁自称**：不写「本站收录/我们收录」，收录行为用无主语句（`收录于 2026-10`），因该句可能进 `WebPage.description`/`ItemList`，第一人称被第三方聚合后指代会错。
- ⚠️ 落地前先处理**同名站点重复**：忽略大小写共 **10 组同名**，分三档处置（以主方案 §0.2 为准）：
  - **A 可自动归一（4 组）**：Cloudflare `cloudflare.com`→`www.`｜Cursor `cursor.com`→`www.`｜魔搭 ModelScope `modelscope.cn`→`www.`｜Midjourney `midjourney.com`→`www.`

  - **误报保留**：`HELM`(crfm.stanford.edu/helm/) vs `Helm`(helm.sh) —— Stanford 评测基准 vs K8s 包管理器，同名异物；`LangGraph` 开源仓库(github.com/langchain-ai/langgraph) vs 产品页(langchain.com/langgraph) —— 不同意图，合并会丢信息。

## 3. 薄内容判定与处置

| 档位 | 判定标准 | 命中量 | 处置 |
|---|---|---|---|
| **厚** | 有 ≥10 条真实条目 + 独立结构化信息 | 首页(1020 链接)、分类 ≥10 站：**64 个**、标签 ≥10 站：**17 个**、插件详情：**64 个** | index,follow；进 sitemap；优先做 title/desc 升级 |
| **中** | 5–9 条，或≥1 个结构性增值块 | 分类 5–9 站：**68 个**、标签 5–9 站：**65 个**、站点 desc 40–79 字：**59 个**、有核验时间：**146 个** | index,follow 但**必须在 4 周内补上增值块**，否则降为薄档 |
| **薄** | ≤4 条，或正文 <60 字且无可补数据 | 标签 <5 站：**998 个（92.4%，含 1 个 0 站点）**、分类 <5 站：**462 个（77.8%，含 1 个 0 站点）**、站点 desc<20 字：**71 个**、无核验时间：**874 个**、合集 4 个（各 3–6 条） | **一律 `200 + noindex,follow`**（见下），不进 sitemap |
### 薄标签的处置：一律 `200 + noindex,follow`，301 已撤销（三方定稿）

我初稿是一刀切 `noindex`，seo-optimizer 主张全 noindex，link-strategist 一度采纳我的「1 站 301」，**但 301 最终被撤销**——它与「站点页展示自身标签」构成自指回环：`/site/{id}` 展示 `#foo` → `/tags/foo`（仅含该站）→ 301 → `/site/{id}`。即使站内断链，外部链接/书签/聚合引用仍会触发，而 Google 对自指跳转是「忽略」，等于白做。**故 301 全撤。**

| 档位 | HTTP | 索引 | 说明 |
|---|---|---|---|
| ≥5 站点（**82 个**） | 200 | **index**，进 sitemap | 有独立信息量 |
| 2–4 站点（**287 个**） | 200 | `noindex,follow` | 有独立列表内容，不该 404 |
| 1 站点（**710 个**） | 200 | `noindex,follow` | 内容 ≡ `/site/{id}`；页面保留，卡片断链 |
| 0 站点（**1 个**，`probe`） | 200 | `noindex,follow` | 标签名存在；`probe` 疑为测试残留，应清理而非靠 404 兜 |
| **标签名不存在** | **404** | — | 唯一该 404 的情形 |
**「页面保留」与「链接断开」是两件事**：710 个页面仍 200、仍可被外部访问，只是站内不再链——理由是**自指循环**（1 站标签出现在自己站点的卡片上，点进去是「只含这一个站点」的列表页，原地绕圈），而非页面被跳走。配套改动：卡片 `#tag` 现为 `<Link>`（`app/site/[id]/page.tsx:384-396`、`app/tags/[slug]/page.tsx:85-88`），降级须与上表对齐——**保留 369 个**（82+287）、**断链 710 个**（1 站）；只做一半会造出成片「点了没反应」的死链。


### 分类 hub：数据支持建 132 个，但**本轮不做**

594 个分类里 **≥5 站点 132 个**，去重覆盖 **1005 个站点 = 98.5%**——建 132 页即可让 98.5% 的站点有分类入口（`sum(n)`=1206 是父子重复计数）。**但本轮不建**：`categories.anchor` **488/594 含斜杠**、101 个纯 UUID，不能作 URL 段，且 `/api/categories` 不返回 siteCount → 需先做 `slug` 数据迁移。另 **2 组同名分类**（`操作系统`、`语言` 各 2 条且都在 ≥5 集合内）会产出同名 hub + 重复锚文本，消歧前不要建。详见 §5 口径说明。

- **内容是错的，不是缺**：`github.com` 一键就吃掉 76 个站（占渲染量 **78%**），把所有仓库型页面都归到「代码托管平台」平替下。实测 `hey`（HTTP 压测 CLI，`github.com/rakyll/hey`）返回「GitLab / Gitee 是你的平替」——**明显事实错误**。
- 25 条种子**全部没有 `targetSiteId`** → `page.tsx:457` 的 `targetSiteId ? <Link> : <span>` 恒走外链分支 → **零站内跳转**（此条成立）。`complementary` 种子 **0 条** → 生态搭配区块永不渲染（此条成立）。
- 三次错判留痕：①只测 Midjourney（`total:0`）就断言「全站空白」——**n=1 外推**；②按精确相等算得 16 站 / 1.57%——**没读匹配源码，漏了 `includes` 语义，差 6 倍**；③link-strategist 的 27.5% 是**抽样排序偏差**（前 40 条含 12 个种子站）。
- **同一函数的其他产物也受此影响**：`actions` 被 76 个仓库型站点整站继承（`github.com` 键的「搜开源库 / Trending」），渲染在**首页卡片**（`navigation-card.tsx:354/498/512`）与 peek 弹窗（`:139`），而非 `/site/[id]`；对「一个具体仓库」而言，用户要的是它的文档/Issues，不是「去 GitHub 搜开源库」——属动作集错配，危害低于平替一档。
- **仍然成立**：`relationsDegraded` 只在 fetch 抛错时置真（`navhub-api.ts:536`），`total:0` 时区块与降级提示都不渲染 → 空白且无解释；真报错时那句「关系网络暂时不可用（服务未响应）…重试」是**误诊**。

**文案结论（定性变了：不是「几乎没覆盖」，是「覆盖 9.7% 但内容错」）**：①**元信息与页面均不得把「平替」当收录价值主张**——1 个错标比 100 个空白更伤人，用户会记住「这个导航站说 Gitee 是 hey 的替代品」。②在**子串匹配改为精确全等或 `siteId` 白名单**之前，平替文案一律不下发；否则补完 `targetSiteId` 只是把错误从「外链」变成「站内错误链接」，反而更难纠正。③生态搭配（complementary 0 条）可直接删除该区块与相关文案。④修复后仅对白名单站点启用，措辞须落到真实平替对象（如 Cursor 页 vs Continue.dev、GitHub Copilot）。

## 7. 红线（本报告所有公式的约束）

1. **不编造数字**：`{N}` 一律实时查，查不到删句，不写「海量」「众多」「N+」。
2. **不编造排名、口碑与指标**：`visit_count`/`trend_score`/`install_count`/`star_count` 全 0 或全 1 时禁「热门」「最受欢迎」「N 人使用」「N 星好评」。**另有已上线的硬编码指标**：`ECOSYSTEM_MAP` 的 `ollama.com`/`excalidraw.com` 两键写死 `githubStars: 125000 / 86000`，经 `navigation-card.tsx:176/304/470` 渲染为「125k / 86k」星标徽章（客户端渲染，用户可见，爬虫不可见）——**这是无刷新机制的死数，必然漂移**，应删除或加「约 · 截至 {日期}」并接真实数据源。
3. **不承诺不存在或错误的区块**：平替覆盖 9.7% 但含 76 站错误标注、生态搭配 0 站、`site_facets` 0 行、`metadata` 全空 → 「平替/生态关联」「适合谁」「分面属性」在数据修正前一律不落地。**宁可页面短，不可页面假**——1 个错标比 100 个空白更伤人。
4. **不注水**：不为凑 60 字加形容词；≤4 站点标签（**998 个**）就是不写描述，按 §3 的 `200 + noindex,follow` 处置，不硬造。5. **不堆关键词**（desc 内同类词只留一个）；**不改技术事实**（URL/状态码/核验时间照实，Claude 实测 403、Unsplash 实测 401，不得标「SLA 正常」）。
