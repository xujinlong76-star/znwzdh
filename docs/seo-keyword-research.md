# NavHub 关键词与落地页优先级研究

> 关宇霖 / 关键词研究与聚类策略。所有数字来源于 `data/navhub.db` 实测与 SERP 实况，**不含任何搜索量/竞争度估值**。

## 0. 数据基线（含 3 处对原假设的修正）

| 项 | 实测 |
|---|---|
| 站点 | 1020 条，all enabled，description 均长 **28.2 汉字**（947 条落在 20–49 字，仅 2 条 50–89 字，0 条 90+） |
| 分类 | 594 条（106 根 / 488 子），**仅 5 条有 description**，489 条 0 站点，≥5 站点 99 个，≥10 站点 63 个 |
| 标签 | 1080 条，**0 条有 description**；≥5 站点 82 个，≥3 站点 203 个；均每站 2.19 标签，0 个无标签站点 |
| 合集 | 4 个，各含 5/6/4/3 个站点（共 18），均有 description |
| 插件 | 64 个，description 全填；kind 分布 site-pack 30 / bundle 14 / theme 10 / workspace-preset 7 / search-pack 3；`install_count>0` 仅 11 个 |

**三处修正（影响策略，必须先读）**
1. `site_relations` 表 **0 行** —— 「平替/生态/上下游」只有 schema 没有数据。任何以平替图谱为主词的词簇目前**无法落地**。
2. `featured=0`、`trend_score=0`、`visit_count=0` 全站为 0 —— `/hot` 无真实热度信号，榜单类标题**禁止**写「访问量排行/最热」。
3. `categories.anchor` 是 UUID（仅 `cat-ai`、`cat-dev` 等 3 个可读），`title_en` 基本为空 —— `/category/[slug]` 不能复用 anchor，**必须先造 slug**，这是分类页的第一阻塞项。

## 3. 词→页面映射与优先级矩阵

映射总览：C1/C2/C4/C5/C6/C7/C9/C10 → `/category/[slug]`（需新建）；C3 → `/` `/hot`；C8/C12 → `/tags/[slug]`；C11 → `/marketplace/[slug]` + `/collections/[slug]`；K4 → `/graph`；全簇品牌词 → `/site/[id]`。

评分：综合 = 就绪度×0.4 + 意图明确度×0.35 + (6−实现成本)×0.25，×20 归一；规模系数 ≥50 页 1.0 / 10–49 页 0.9 / <10 页 0.75。需求信号据 SERP 竞品覆盖形态判断，**非搜索量**。

## 4. 标题与 Description 公式

长度红线：**title ≤ 60 半角视觉宽（中文按 2 计，即 ≤ 30 全角字符，含品牌后缀）**；**description 60–78 汉字**，前 30 字必须含主词 + 一个真实数字。

**站点详情 `/site/{uuid}`**
- T1（工具名主搜）：`{工具名} - {一句话定位≤16字} | NavHub` → `SWR - Vercel 出品的 React 数据请求库 | NavHub`
- T2（平替意图，待 C8 数据）：`{工具名} 平替：{N} 个可替代工具 | NavHub`
- T3（中文/国产意图）：`{工具名} 中文版与国内替代方案 | NavHub`
- D1：`{工具名} 是{类别}领域的{定位}，{核心特点≤20字}。{开源/免费/国产等事实一句}，附官网入口、{M} 个同栈工具与{分类名}替代选择。`
  （现库内均长 28 字，可直接把 description 扩到该模板的 60–78 字区间）

**分类页 `/category/[slug]`**（每分类一份）
- T：`{分类名}工具推荐 - {N} 款精选 | NavHub` → `数据库与存储工具推荐 - 21 款精选 | NavHub`
- D：`{分类名}涵盖{一句话定义}。NavHub 收录 {N} 个相关工具，含 {Top3 工具名} 等，可按{开源/国产/免费}筛选，附官网入口与替代方案对比。`
- 不加年份（除榜单页），避免年度维护成本与过期信号。

**标签页 `/tags/[slug]`**
- T：`{标签名}相关工具 - {N} 个 | NavHub` → `开源相关工具 - 123 个 | NavHub`（不用「合集」以免与 collections 语义撞车）
- D：`{标签名}类开发者工具共 {N} 个，包含 {3 个站点名}。{该标签共性一句话，需按批生成}。支持一键直达官网与相似工具推荐。`

**合集 `/collections/[slug]`**
- T：`{合集标题} - {N} 个工具精选清单 | NavHub`
- D：`{合集标题}：{合集 description}。共 {N} 个工具，覆盖{子主题 1}、{子主题 2}，适合{目标人群}按路线依次选用。`

**插件 `/marketplace/[slug]`**
- T：`{插件名} - {kind 中文}（{N} 站点/主题）| NavHub`（kind 映射：site-pack=站点包 / bundle=组合包 / theme=主题 / workspace-preset=工作台预设 / search-pack=搜索引擎包）
- D：`{插件名} 是 NavHub 的{类型}，{做什么}。含 {N} 个站点，支持一键导入，{授权/版本}。`

**榜单 `/hot`**
- T：`{榜单名} - 开发者工具{周期}榜 | NavHub`（**禁用**「访问量排行」）
- D：`NavHub{榜单名}：按{收录时间 / 分类厚度 / 生态活跃度}排序的 {N} 个工具，{周期}更新，覆盖 AI 工具、开发者工具与效率软件。`

**首页**
- T：`NavHub 导航 - 1020 个开发者与 AI 工具收录`
- D：`NavHub 收录 1020 个开发者工具与 AI 产品，594 个技术分类、1080 个标签，支持中文语义检索、技术栈图谱与平替查找，面向中文开发者与独立开发者。`

## 5. 内容缺口（按阻塞程度排序）

| 缺口 | 影响词簇 | 需补内容 | 最小可交付 |
|---|---|---|---|
| 分类 `anchor` 全为 UUID、`title_en` 空 | C1 C2 C4–C7 C9 C10 | 生成可读 slug（拼音或语义英文），唯一性校验 | 99 个分类的 slug 映射表 |
| 分类 description 仅 5/594 | 同上 | 每分类 60–80 字导语（定义 + 收录数 + 3 个代表工具） | 63 个 ≥10 站点分类导语 |
| 标签 description 0/1080 | C12 C8 | 每条 80–120 字（类别定义 + 覆盖范围 + 选型提示） | Top 30 标签导语 |
| 站点页均长 28 字 | 全品牌词 | 「是什么 / 适合谁 / 替代与同栈」三段，合计 ≥120 字 | 模板 + Top 200 站点填充 |
| `site_relations` 0 行 | C8 K5 | 平替/互补/上下游关系对 | 先覆盖 Top 100 工具的平替关系 |
| 排行榜无信号（featured/trend/visit 全 0） | C3 榜单词 | 定义可验证排序：收录时间、分类厚度、GitHub stars（若可采） | 口径文档 + `/hot` 文案改造 |

| 489 个 0 站点分类 / 878 个 <5 站点标签 | 全站质量 | 门控：分类 ≥5 站点、标签 ≥3 站点才可索引，其余 noindex 或合并 | 阈值规则 |

## 6. 竞争面判断

**SERP 构成（实测 4 个站点）**
- **ai-bot.cn**：三层结构最成熟 —— 首页（Banner 广告 + 热门/最新 Tab + 9 大类横向铺开）→ `/favorites/{英文slug}/`（如 `best-ai-image-tools`）→ `/sites/{id}.html`。title 模式为「品牌 | 数量卖点 + 品类 + 导航大全」，详情页为「工具名 - 定位 - 品牌」。已用英文 best- 型 slug 与「1000+ 工具」数量叙事占位。
- **code-nav.cn**：`/tool` 单页列表 + 侧栏分类，**无独立分类 URL** —— 分类页 SEO 是其最大弱项，正是我们的机会。
- **devpages.io**：以 GitHub stars 做**可验证排序**（Top 20），打「不收费上榜、不编评分」的透明叙事。
- **uskill.cn/zh-CN/urls**：单页信息堆砌，弱竞争者。

**规律**：头部被大导航站（ai-bot.cn、haohao.com、360AI导航、发现AI）以「数量 + 更新频率」占据；中段是 CSDN/掘金式的「AI 工具导航汇总」list（抢词但不做站）；技术站（MDN、掘金）瓜分「工具推荐」长尾。它们普遍**只做泛 AI 分类**，不做深度技术栈切分。

**我们的差异化（按可信度排序）**
1. **分类厚度可验证**：`数据库与存储` 21 个、`IaC 与云厂商` 17 个、`组件库与 UI` 14 个 —— 竞品停留在「AI写作/AI图像」这种粗类。用「21 款数据库工具」这类真实数字打，比「10000+ 工具」更可信。
2. **技术栈图谱 `/graph`**：SERP 无同形态对标物，是唯一可独占的品类词（K4）。
3. **中文语义检索 + 1020 条真实收录**：可做「中文搜得到」的定位，但前提是 `?q=` 支持与可索引检索页（当前没有，属未来项）。
4. **开源自托管专类**：`开源自托管与替代方案` 11 站点 + `自托管`/`开源` 标签，切「平替/私有部署」高转化词 —— 但需先补关系数据。
- **不打**：「AI 工具导航」头部词正面竞争，只做其长尾（按分类/标签切）。

## 7. 风险与前提（必读）

1. **无搜索量数据**。本报告全部需求判断来自 SERP 形态与站内厚度，**未使用任何具体搜索量/竞争度数值**。上线前须用 Google Keyword Planner（中文区）、5118、站长工具、Ahrefs 中文库复核 C1–C12 的实际量与难度，据此调整第 3 节矩阵的需求信号列与排序。
2. **3 个数据阻塞项**：`site_relations` 0 行（C8/K5 无法落地）、排行榜三字段全 0（榜单文案受限）、分类 anchor 为 UUID（分类页无法上线）。这三项不解，第 3 节中第 8/9/7 项无法执行。
3. **索引预算风险**：594 分类 + 1080 标签若全量开放将产生大量薄页，必须先设门控阈值（分类 ≥5 站点 / 标签 ≥3 站点），否则拖累全站质量。
4. **URL 结构**：站点页为 `/site/{uuid}`，无 slug；建议实现者评估 `{uuid}-{slug}` 或 `/tool/{slug}` 的可读化改造，属于技术决策，不在本报告范围。
5. **中文 slug**（标签）在 Google 结果中会 percent-encode 展示，建议保留拼音/英文别名。
6. 本报告不含技术实现，代码与路由方案由 SEO 优化师承接。
